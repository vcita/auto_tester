# CP Multi-Booking — Summary Component — Detailed Script

> Status: Migrated from automation-js scheduler page objects + verified by focused run.
> Generated By: migration (VCITA2-14228).

## Initial State
- URL: public livesite `{CP_VITRAGE}/site/{pivot_uid}` (anonymous; no login).
- Prerequisites (from _setup): service1 (20m), service2 (40m), Staff1/Staff2, client, CP multi
  booking enabled, FF multi_appointment_client_booking.

All scheduler interaction happens inside the `cp_iframe`; helpers scan every frame for the
target selector (`_cp_frame_with`) because the livesite shell nests the iframe differently.

## Actions

### Step 1: Pick "Schedule Now" on the livesite
- Helper: `schedule_now(page, context)`.
- Navigate to `{CP_VITRAGE}/site/{pivot_uid}`, click the action card `.action-content`
  with text "Schedule Now" (legacy `Livesite.clickAnAction`).
- Wait for the scheduler services page `[data-qa="ServiceCategoryPage"] .service-item`.
- CHOSEN: `.action-content` filtered by text — matches the legacy `actionCard` selector.

### Step 2: Select service1 + service2, continue from calendar
- Helper: `select_services(page, ["service1", "service2"])` then
  `pick_default_timeslot_and_continue(page)`.
- Click each `span.service-title[data-style-id]` by name, click `.summary-card__cta`
  (legacy `ServiceList.selectServices`), then pick `button.time-slot` (first) and click the
  multi-booking confirm `.summary-card__cta` (legacy `CPCalendar.continueToIntake(is_multi_booking=true)`).

### Step 3: Assert the summary component
- Helper: `assert_summary_component(location="At TLV", duration="Duration: 1 hour",
  providing_staff="With Automation test business")`.
- Read data-qa fields (legacy `BookingSummary`): `booking-detail-service-location`,
  `booking-detail-duration`, `booking-detail-staff-name`. Assert date/time present
  (`booking-detail-start-date`/`booking-detail-start-time`) — legacy `default` = existence.
- Duration 1 hour = service1(20) + service2(40).
- DEVIATION (staff name): the legacy table hardcodes "With Automation test business" because
  the legacy auto-account is literally named "Automation test business". The auto_tester
  isolated account name varies per run, so the default providing staff = "With <owner display
  name>" is resolved dynamically: _setup reads the owner staff display_name from the staff
  list and the test asserts `f"With {owner_display_name}"`. Same behavior (default staff shown),
  account-name-agnostic.

### Step 4: Fill intake form + confirm
- Helper: `fill_intake_and_confirm(first_name="jimmy", last_name="slipping", email=...)`.
- Fill `input[type='email']`, the labeled First/Last Name inputs (legacy intakeForm xpath),
  click confirm `.submit-button span, .summary-card__cta`.

### Step 5: Assert booking confirmation
- Helper: `assert_booking_confirmation(title="Booking request sent!")`.
- Wait for `[data-qa="ConfirmBooking"]`, read `.text-container span.confirmation-title`.

### Step 6: Open the CP meeting page + assert
- Helper: `open_meeting(page, "service1")` then `assert_meeting(...)`.
- In the same post-booking session: switch into cp_iframe (`.v-application--wrap`), click
  `.business-title` (dashboard), click `[data-qa='client-area-menu-bookings']`, click the
  booking whose `.booking-title` is service1.
- Assert `.booking-title`=service1, `.state.booking-state`="Pending approval", and a
  `[data-qa='linked-appointment-row-title']` contains service2.

## Success Verification
- Summary shows At TLV / Duration: 1 hour / default staff; confirmation "Booking request
  sent!"; meeting page service1 Pending approval linked to service2 (real CP data, no toasts).
