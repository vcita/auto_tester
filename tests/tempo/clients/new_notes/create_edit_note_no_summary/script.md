## CRITICAL: UI structure discovered (differs from legacy add_note/edit_note)

The new POV notes UI is materially different from the legacy notes dialog. Key facts verified in MCP:

1. **Matter page tabs + notes list live in nested iframes** (same as legacy):
   - Outer: `page.frame_locator('iframe[title="angularjs"]')`
   - Inner: `outer_iframe.frame_locator('#vue_iframe_layout')`
   - The **Notes tab** is in the **inner** frame; the **"Add note"** button is in the **outer** frame (header).
2. **The Add/Edit note popup renders in the TOP-LEVEL page document — NOT in any iframe.**
   (Legacy used `#vue_wizard_iframe`; the new popup uses no wizard iframe at all.) So popup
   locators are plain `page.locator(...)` / `page.get_by_role(...)`, with **no** `frame_locator`.
3. **Stable `data-qa` selectors exist on the popup** (preferred per prefer-data-qa-selectors):
   - Add popup title: `input[data-qa="add-note-dialog-title"]` (placeholder "Title")
   - Add popup body: `#add-note-dialog-editor_textarea` (TinyMCE `contenteditable`)
   - Edit popup title: `input[data-qa="edit-note-dialog-title"]`
   - Edit popup body: `#edit-note-dialog-editor_textarea`
   - Footer Save: `button[data-qa="vc-footer-Save"]`; Cancel: `button[data-qa="vc-footer-Cancel"]`
4. **The preview card shows the BODY + timestamp only — NOT the title.** The card carries class
   `VcNotePreviewCard__header--no-heading` and an empty `__heading` div. The **title is still saved**
   (verified: it is prefilled in the edit popup). So the create-verification asserts on the **body**
   text on the card, and the title is verified via the edit popup prefill (Step 6). This is a UI
   design choice of the preview card, **not a bug**.
5. **Card data-qa is dynamic**: `data-qa="NotePreviewCard-<random>"`. Sub-elements carry the same
   prefix with stable suffixes:
   - Card root: `.VcNotePreviewCard[data-qa^="NotePreviewCard-"]`
   - Card body text: `[data-qa$="-body"]` (one per card; holds ONLY the body text, no timestamp)
   - 3-dot trigger: `[data-qa$="-actions-trigger"]`
   - Edit menu item: `[data-qa$="-actions-edit"]` (text "View/ Edit"); also `-actions-clone`, `-actions-remove`.
6. **No AI chrome present** with `note_summary` OFF — verified the card contains no
   summary/AI/generating elements.
7. **CRITICAL — scope every card lookup to the Notes-tab content (`.notes-wrapper`)** (HEAL 2026-06-28):
   The SAME note body renders in TWO places, both using `NotePreviewCard` data-qa:
   - **Notes tab list** — `.notes-wrapper` (`.notes.matter-engagement-tab` → `.notes-list`), the card
     we assert on. The card id is random (`NotePreviewCard-<random>`).
   - **"Recent note" side-pane widget** (matter summary, `v-expansion-panel`, OUTSIDE `.notes-wrapper`)
     — a duplicate card with the STATIC data-qa `NotePreviewCard-recent` (body = `NotePreviewCard-recent-body`).
     When this panel is expanded, the unscoped `[data-qa^="NotePreviewCard-"]` / `[data-qa$="-body"]`
     selector matches the body in BOTH places → **Playwright strict-mode violation (2 elements)**.
   - **Fix**: scope every card/body/trigger lookup with `inner_iframe.locator('.notes-wrapper')` (unique,
     count==1). Verified: with the Recent-note panel expanded, unscoped body match = 2, `.notes-wrapper`-scoped
     = 1. `.notes-wrapper` is the stable wrapper for the active Notes window-item; there is NO `role="tabpanel"`.
8. **CRITICAL — match body text EXACTLY** (HEAL 2026-06-28): `filter(has_text=...)` / `get_by_text` are
   substring matches by default, so `"Automation note body"` ALSO matches the edited card
   `"Edited automation note body"`. Assert on the `[data-qa$="-body"]` element with an anchored regex
   (`re.compile(r"^Automation note body$")`) or `get_by_text(..., exact=True)`. Verified: anchored/exact
   match → exactly 1; substring → 2 once an "Edited..." note exists.

## Step 5: Verify the note card appears with body content and NO AI chrome

- **Action**: Verify (create outcome — real data check, not a toast)
- **Target**: The note preview card in the inner-iframe notes list

**LOCATOR DECISION:**

| Option | Pros | Cons |
|--------|------|------|
| `inner_iframe.locator('.notes-wrapper .VcNotePreviewCard').filter(has=body-exact)` | Scoped to Notes tab (excludes Recent-note widget); card root | Two-locator filter |
| `inner_iframe.locator('[data-qa^="NotePreviewCard-"]').filter(has_text=body)` | Simple | **BROKEN**: matches Recent-note side-pane duplicate AND card root + `-body` child → strict-mode 2+ |
| `inner_iframe.get_by_role("listitem").filter(has_text=body)` | Semantic | Not scoped; same duplicate problem |

**CHOSEN**: Card root scoped to `.notes-wrapper`, filtered by a child `[data-qa$="-body"]` whose text matches
the body EXACTLY (anchored regex). `.notes-wrapper` excludes the "Recent note" side-pane widget; the
anchored body-element match avoids the `-body`/card-root double-match and the "Edited..." substring collision.

**VERIFIED PLAYWRIGHT CODE**:
```python
created_note_body = "Automation note body"
# Scope to the Notes-tab content (.notes-wrapper) — NOT the "Recent note" side-pane widget.
# Match the card-body element with an anchored regex so "Edited automation note body" never matches.
note_card = inner_iframe.locator('.notes-wrapper .VcNotePreviewCard').filter(
    has=inner_iframe.locator(
        '[data-qa$="-body"]', has_text=re.compile(rf"^{re.escape(created_note_body)}$")
    )
)
expect(note_card).to_have_count(1, timeout=5000)
expect(note_card).to_be_visible(timeout=5000)

# No AI chrome: the card must not contain a summary/AI/generating section (note_summary OFF)
expect(note_card.filter(has_text=re.compile(r"summary|generating", re.I))).to_have_count(0)
```

- **How verified**: In MCP (clean matter), scoped card count == 1, visible, AI-chrome count == 0. **Proof of
  scoping**: after expanding the "Recent note" side-pane panel, the UNSCOPED `[data-qa$="-body"]` body match = 2
  (`NotePreviewCard-recent-body` + the list card), while the `.notes-wrapper`-scoped match = 1. **Important**:
  the preview card shows the **body + timestamp only, not the title** (card has class
  `VcNotePreviewCard__header--no-heading`). Title persistence is verified separately in Step 7 (edit popup prefill).
- **Wait for**: scoped card count == 1 and visible; AI-chrome count == 0
- **Fallback locators**: `inner_iframe.locator('.notes-wrapper [data-qa$="-body"]').filter(has_text=re.compile(rf"^{re.escape(created_note_body)}$"))`

## Notes for Phase 3 (test.py)
- Requires `import re` (AI-chrome regex) and `from playwright.sync_api import expect`.
- The popup is at the **top-level page** — do NOT wrap popup locators in `frame_locator`.
- The Notes tab, "Add note" button, and the notes list/cards ARE in iframes (Add note = outer,
  tab + cards = inner). Keep `outer_iframe` / `inner_iframe` exactly as defined in Step 1.
- Card data-qa is dynamic — use the `.VcNotePreviewCard` root + `[data-qa$="-body"]` /
  `[data-qa$="-actions-trigger"]` / `[data-qa$="-actions-edit"]` suffix selectors.
- **ALWAYS scope card lookups to `inner_iframe.locator('.notes-wrapper')`** so the "Recent note"
  side-pane widget (static `NotePreviewCard-recent`, OUTSIDE `.notes-wrapper`) is never matched —
  otherwise you get a Playwright strict-mode violation (2 elements). There is NO `role="tabpanel"`.
- **Match body text EXACTLY** with an anchored regex (`re.compile(rf"^{re.escape(body)}$")`) on the
  `[data-qa$="-body"]` element — substring `has_text`/`get_by_text` collides "Automation note body"
  with "Edited automation note body".
- Matter-entity agnostic: this flow uses no matter-label text; locators are role/data-qa based.
